It gives `ai-proposal` 120 s but all other Task routes 20 s. A fetch timeout, network error, oversized/non-JSON response, or parse failure becomes `UPSTREAM_UNAVAILABLE` HTTP 502. It otherwise preserves the upstream response status and sanitized JSON. Correlate request ID/timestamp and response `reasonCode` with logs.
2. `TaskAccountService.bind` validates owner/current candidate/expiry, RPC receipt and transaction, expected deployment input, chain ID, runtime template, and all immutable getters, then locks and writes `BOUND` with `ACCOUNT_BOUND` in a transaction. Intentional invariant failures call `require` and map to `CHAIN_NOT_READY` HTTP 409; `APPROVAL_INVALIDATED` is 409. `TaskAccountRpc` has a 12 s timeout **per RPC call** and throws on transport/provider errors. An unexpected RPC or DB exception reaches `GlobalExceptionHandler` as `INTERNAL_ERROR` HTTP 500. The confirmed database connection limit is therefore a plausible direct cause of the bind 500; source alone cannot exclude RPC/provider or another uncaught error. The read-only `PREPARED` lookup implies no persisted BOUND transition in that snapshot.
