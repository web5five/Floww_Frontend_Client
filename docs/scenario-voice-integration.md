## Behavior and boundaries

- All three purchase cases expose a Task-bound voice entry from the journey; chat keeps its microphone panel and full voice link. The full voice page returns to the same Task and the prior journey step when opened there.
- Voice or a fixed case selection displays an explicit on-screen confirmation. The model tool output and selecting a case alone make no Task, quote, proposal, attempt, payment, or signer request. After the user confirms, the page re-reads the existing owner-scoped Task, checks its exact ID/status/expiry/attempt and local uncertain/stop markers, and stages a two-minute, one-use, same-tab intent for the chat route. The chat consumes it and uses the existing same-Task quote/decision flow. Duplicate tab cloning can copy session storage; authoritative Task checks and server idempotency remain necessary.
- A confirmed B/C choice remains the active case after reload when more than one local case maps to the same Task. A wrong Task ID returned from a read blocks continuation. Logout or wallet disconnect during a pending read invalidates the voice action. Existing decisions, expired/stopped Tasks, and uncertain quote/decision outcomes remain read-only until their existing recovery path is used.
- The server-only voice gate remains `FLOWW_VOICE_ENABLED === "true"`; the public UI gate remains `NEXT_PUBLIC_FLOWW_VOICE_ENABLED === "true"`. Both are off by default and no frozen submission deployment setting changed. The Task snapshot read has one 20-second headers-plus-body deadline for hosted cold starts; the provider call has one 12-second deadline; the browser setup limit is 40 seconds. The OpenAI key remains server-only, OpenAI guides the conversation, and Kiln/Task policy retain purchase authority. There is no voice-triggered payment or wallet approval.
