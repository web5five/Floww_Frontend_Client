# 신우 프론트엔드 최종 상태

기준 시각: 2026-09-30 KST

## 담당 범위

신우 담당은 다음 최소 프론트엔드 데모 흐름과 웹·모바일 화면 완성도입니다.

1. 지갑 또는 Magic 로그인 진입
2. 정상 구매, 예산 초과, 수취인 위반 시나리오 선택
3. 같은 Task를 유지한 진행 화면
4. 정상 구매의 성공 결과 또는 B/C 차단 결과 표시
5. 최신 프론트엔드 브랜치와 커밋 공유

백엔드 배포 오류 해결, 실제 Sepolia 결제 실행, 이행 완료 검증, 차단 로그 수집은 팀 통합 작업이며 신우 단독 담당으로 기록하지 않습니다.

## 프론트엔드 구현 및 로컬 검증

- 소개 화면에서 세 시나리오를 직접 선택하고 ALLOW/DENY 판단과 증거를 확인할 수 있습니다.
- 로그인 뒤 `/pharmacy`에서 시나리오를 선택하면 `/journey/{taskId}/{step}`의 조건, 판단, 승인, 결과 단계로 이어집니다.
- 정상 흐름은 사용자 승인 전 결제를 실행하지 않고, 승인 후 실행·결제·이행 상태를 구분해 표시합니다.
- B 예산 초과와 C 수취인 위반은 DENY 사유를 표시하고 서명·브로드캐스트·트랜잭션 해시가 없음을 보여줍니다.
- 새로고침 중 미확정 실행을 복구하고 중복 배포·중복 결제를 막는 클라이언트 처리가 있습니다.
- 데스크톱과 모바일에서 핵심 흐름 테스트가 통과했습니다.
- UI는 파란 FLOWW 표시, 굵고 진한 텍스트, 밝은 판단 카드, 단계별 여백, 1300px 이하 사례/증거 탭으로 정리했습니다.

## 배포본에 대해 팀이 확인한 사실

- 실제 Magic 로그인과 관리자 로그인을 확인했습니다.
- Admin에서 동일한 Task와 정책·이벤트 기록을 확인했습니다.
- 배포 프론트에서 B 예산 초과 시나리오가 실제 서버 DENY 결과까지 도달한 것을 확인했습니다.
- 성공 시나리오는 Sepolia 구매 계정 배포까지 확인했습니다.
- 그 이후 서버 연결에서 DB 동시 연결 한도 문제가 발견됐으며 배포 설정을 조정 중입니다.
- 따라서 실제 Sepolia 결제와 이행 완료는 아직 확인되지 않았습니다.
- C 수취인 위반의 배포본 검증과 B/C의 백엔드 무결제 증거 보존은 아직 필요합니다.
- Vercel 접근 요청과 팀 테스트 접근 방법은 확인 중입니다.

## 최종 제출 전 남은 항목

| 항목 | 현재 판정 | 필요한 증거 |
|---|---|---|
| 실제 로그인 기반 hosted 성공 E2E | 진행 중 | 동일 Task의 결제 TX, receipt, 이행 검증, COMPLETED |
| hosted B 예산 초과 DENY | 동작 확인, 증거 보존 필요 | Task ID, DENY 사유, signing/broadcast 0, txHash 없음 |
| hosted C 수취인 위반 DENY | 필요 | Task ID, RECIPIENT_NOT_ALLOWED, signing/broadcast 0, txHash 없음 |
| 배포 프론트 새로고침 복구 | 필요 | 새로고침 전후 동일 Task/결제 상태와 중복 지급 없음 |
| Admin 브라우저 확인 | 팀 확인 완료, 캡처 보존 필요 | 동일 Task의 정책·이벤트 화면 캡처 |
| 3분 데모 영상 | 필요 | 최종 배포 SHA로 녹화한 영상 링크 |
| 최종 덱 PDF | 필요 여부 확인 후 첨부 | 제출 패키지의 실제 PDF 파일 또는 공개 링크 |
| 릴리스 매니페스트 | 최종 push 뒤 갱신 필요 | 프론트·백엔드·컨트랙트 최종 SHA와 상태 |
| 제출 폼 | 필요 | 제출 완료 화면 또는 확인 메일 보존 |

## 완료 판단 원칙

로컬 fixture 테스트 통과를 hosted 성공으로 기록하지 않습니다. 계정 배포만으로 결제·이행 완료라고 기록하지 않습니다. 팀 채팅에서 확인한 동작은 캡처, Task ID, 로그 또는 링크가 제출 패키지에 보존돼야 최종 증거 완료로 판정합니다.
